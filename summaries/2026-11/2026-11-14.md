# FPP Updates — November 14, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

27 commits, 21 from community contributor darylc (including 2 plain merge commits) and 6 from jessica12ryan. The main themes are HDMI/display settings, boot and WiFi reliability, media-storage diagnostics, UI polish, and a UDP output buffer fix. Five commits (a UDP de-duplication fix, a related comment cleanup, and the fan-RPM tooltip work) were originally made November 10–13 but only merged into master in this batch; the rest landed November 14.

## Security

- **A potential memory-corruption bug in UDP output is fixed: the de-duplication buffer that skips sending unchanged frames now grows when an output's channel count changes**, instead of staying a fixed size and risking a heap overflow on write (jessica12ryan).

## Outputs and hardware

- **HDMI settings now respect what each board can actually drive**: a Pi 0-3, Pi 4/5, or BeagleBone Black only sees the video modes its hardware supports, the resolution list is sorted sensibly, and it gains refresh rates (like 1920x1080 at 25/50/100/120 Hz) chosen to keep LED-panel shows moving smoothly (darylc).
- **A new "Force HDMI Mode Timing" setting lets panels that don't advertise a mode in their EDID still get a forced resolution that actually shows a picture** (darylc).
- **The HDMI resolution list no longer drops a value you'd already saved**, which used to make a forced mode look unset and get lost the next time settings were saved (darylc).
- **A Virtual Matrix pointed at a submodel of an HDMI framebuffer output now actually draws**, instead of showing nothing (darylc).

## Stability fixes

- **Boot reliability improved on slow-booting boards (Pi Zero, BeagleBone): cloud-init no longer delays startup, every WiFi adapter reconnects after a slow boot (not just the first one), and Diagnostic Reports that take over a minute to build are no longer dropped before they finish** (darylc).

## Networking

- **Picking a WEP WiFi network now shows a clear "not supported" notice** instead of a key field that never worked, suggesting you switch the router to WPA2/WPA3 or use a wired connection (darylc).
- **Joining an open WiFi network, or one using a 64-character hex security key, now actually works** — both used to be accepted by the Network page but produced a configuration that couldn't connect (darylc).
- **A WiFi scan quirk on some adapters that could peg a CPU core for 30+ minutes is now capped at 5 seconds** before falling back to a normal scan (darylc).

## System and UI

- **It's much easier to tell why FPP can't find or use its media storage**: the "media drive not mounted" banner works again on current images, the "not writable"/"low disk space" banners show the actual folder permissions and disk/inode usage behind the problem, the "media directory missing" banner states exactly which step failed, and a corrupted or relative media-path setting can no longer silently break every page (darylc).
- **Fan speed in the header tooltip, OLED display, and status API now shows as a whole number** instead of "1200.0 RPM", and Celsius readings now show the °C unit like Fahrenheit already did (jessica12ryan).
- **Warning (⚠) icons next to scheduled playlists, commands, and GPIO entries now show their explanation in a proper tooltip that works on touchscreens**, instead of a hover-only tooltip that showed nothing on touch (darylc).
- **The schedule preview's column headings no longer drift up onto the dialog's title bar** while the preview is still opening (darylc).
- API reference docs were regenerated to catch up with several earlier fixes; no functional change (darylc).

## Upgrade note

- If you call FPP's WiFi-setup API directly rather than through the Network page, it now rejects a security key that isn't empty, an 8–63 character passphrase, or exactly 64 hex digits — check that scripts or integrations still send a valid key.
- Upgrading an existing Raspberry Pi install disables cloud-init (creates `/etc/cloud/cloud-init.disabled`) to speed up boot; skip this if you rely on cloud-init for something else.
