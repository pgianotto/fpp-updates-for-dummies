# FPP Updates — November 15, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

9 commits, all from community contributor darylc. They fix false "stuck" or "failed" readings on the Upgrade OS page, a boot bug on unusual storage setups, and two bugs where duplicate or restarted Pixel Overlay Models could step on each other's memory.

## Stability fixes

- **The Upgrade OS page could wrongly report a successful update as "did not finish," or show one as still running long after it finished.** This happened when update-log lines got lost during the post-upgrade reboot, the system clock was running behind right after boot, or another operation (like a Rebuild) was holding the update lock. A boot now writes its own marker line to the log, so a finished upgrade is recognized even if its own closing line didn't survive the reboot (darylc).
- **A "Download Only" OS download could get mistaken for a full OS upgrade still in progress, hiding the Upgrade OS button for up to 15 minutes.** Download Only now logs and tracks itself separately from a real upgrade (darylc).
- **Upgrade logs are now saved to disk before the final post-upgrade reboot**, so the lines confirming a successful upgrade are no longer occasionally lost to the reboot itself (darylc).

## System and UI

- **FPP could fail to finish booting if its media storage wasn't a normal device path** — for example certain overlay, tmpfs, or network-mounted setups. Boot now continues normally instead of aborting partway through (darylc).
- **The Storage tab's drive picker now actually lets you clear the "media drive not connected" warning.** It used to open already showing the wrong entry, so re-selecting it did nothing, and the banner's suggested fix — "pick the boot device" — could send your show files to the wrong partition on a Raspberry Pi. The picker and the warning text are both clearer now about which drive is expected and what to pick instead (darylc, PR #3188).

## Outputs and hardware

- **Pixel Overlay Models now refuses to save two models with the same name** and tells you which name clashed, instead of silently keeping only one of them active at runtime (darylc).
- **Fixed two bugs tied to duplicate or restarted overlay models:** a duplicate name used to be able to knock out the shared memory the first model needed, and restarting fppd could leave a model showing leftover pixel data from before the restart instead of starting cleared (darylc).

## Upgrade note

- The system-upgrade log now includes a boot marker line, and a Download Only logs itself under a new `os-download` tag instead of being folded into `os-upgrade`. If you have scripts or integrations that parse `fpp_system_upgrades.log` or poll `/api/system/updateActivity`, double-check they still handle this correctly.
