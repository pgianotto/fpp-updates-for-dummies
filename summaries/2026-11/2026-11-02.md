# FPP Updates — November 2, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

14 commits, ten from Daniel Kulp and four from darylc, mostly a big improvement to File Copy backup and restore plus a batch of small web interface fixes. All landed on November 2, several in the early hours.

## New features

- **Restore settings by area from a File Copy backup.** The backup folder's settings areas can now be read, and a Configuration restore can be done one settings area at a time, just like restoring from a JSON settings file (darylc).

## Stability fixes

- **A restored schedule is used right away.** After a Configuration or All restore from File Copy, the restored schedule now takes effect immediately (darylc).
- **File Copy backups are tidier.** "Plugins" now copies each plugin's own settings, and "Configuration" skips crash reports, uploads and temporary files (darylc).
- The File Copy dialog now finishes properly instead of hanging when its fallback progress feed goes away.
- A rare timing problem in the AES67 audio-over-network sender was fixed.

## MultiSync and updates

- When a remote's resync lands a second off target, audio now gets corrected along with the video instead of drifting.

## Outputs and hardware

- **Pixel string setup fixes.** Start nulls are now counted in a DPI port's pixel and power totals, and End Channel shows whole nodes the first time the page is drawn. An empty smart receiver placeholder no longer gets an automatic overlay model created for it.
- The SPI-WS2801 output page now passes its device list correctly.

## System and UI

- Plugin themes' scripts are now closed properly, so they can't break the rest of the page.
- Drop-down menus with no current value no longer show a stray "undefined" choice.
- Remote content lists now load from the page's own address, avoiding blocked requests.
- Detail pop-ups no longer throw an error when an error response has no text.
