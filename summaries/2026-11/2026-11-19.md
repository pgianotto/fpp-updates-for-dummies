# FPP Updates — November 19, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

26 commits from six contributors. Daniel Kulp did most of the work, across device-identity fixes, boot-hang fixes and general stability; Scott Hanson added a one-click "Open" button for controllers; jessica12ryan fixed a run of shell-injection and HTML-escaping bugs on the network settings page; and Starfield3, Stephen Ripaldi, and tlchandler each contributed one hardware or boot fix.

## New features

- **Output rows for E1.31, ArtNet and DDP controllers now have an Open button next to Ping**, which opens the controller's own web page in a new tab — going through FPP's proxy automatically when the controller isn't one your browser can reach directly. (credit Scott Hanson)

## Security

- **Several holes in the network settings page that could let a crafted interface or device name run commands on the FPP box, or inject HTML into the page, are now closed.** Interface names, device names and settings paths are properly quoted before being used in shell commands, and interface names shown in dropdowns are now HTML-escaped. A related cleanup also fixes a leak where renaming past the tenth network interface left its old config file behind. (credit jessica12ryan)

## Playback and MultiSync

- **MultiSync remotes playing a video playlist now land in sync with the master much sooner.** A remote used to start each clip a few frames behind the master and slowly drift into sync over the whole clip, repeating the same offset at every song change. A remote now learns its own timing offset and applies it up front, so it lines up with the master from the start of each clip instead of catching up partway through.

## Outputs and hardware

- **Fixed a bug on FalconV5 receiver setups where extra, unanswerable status queries could undo the automatic query-spacing added recently**, pushing the query rate back up and eating into the show's frame budget. (credit Starfield3, with a same-day follow-up fix from Daniel Kulp)
- **Fixed a crash on BeagleBone-based "BBBMatrix" panel setups when a panel was configured on more than 8 outputs** — FPP now refuses the extra panel with a warning instead of crashing on startup.
- **Fixed two bugs, found on cape hardware that shares one enable pin across several output ports, that could leave all of those ports dark.** Depending on the order ports were added or removed, the shared pin could end up released — and silently stop responding — while ports were still using it. (credit tlchandler for one of the two fixes)
- **Fixed a crash in WLED support when renaming a segment ran out of memory**; it now just keeps the old name instead of corrupting memory. (credit jessica12ryan)

## Stability fixes

- Crash reports now include a count of fppd's open file descriptors by type, making it much easier to diagnose crashes caused by a slow descriptor leak.
- Fixed a bug where a crash caused by running out of file descriptors produced a report with no stack trace at all — exactly the information needed to diagnose that kind of crash.
- Fixed a crash the first time FPP tried to play audio with no sound server available to connect to.
- Quieted repeated, harmless log errors from an empty leftover config file on some systems, which could otherwise flood the log during playback.
- **Fixed a hang on the first boot after an FPPOS upgrade that could leave a WiFi-only player off the network until it was power-cycled.** Restoring the saved NTP server setting at boot used to wait on a service restart that couldn't actually run yet, so FPP gave up on setting up networking entirely. (credit Stephen Ripaldi)
- **The boot step that restores saved settings now gives up after 45 seconds instead of hanging indefinitely**, so one stuck setting can no longer keep the network from coming up; an interrupted restore is retried automatically on the next boot.

## System and UI

- **Boards that ended up sharing the same identity (UUID) are fixed.** Older FPP images baked in a shared machine ID that survived OS upgrades, and PocketBeagle2 boards with a blank or partially-written EEPROM fell back to it too — so multiple boards could show up on the network reporting the same identity. FPP now recognizes and discards those old shared IDs, repairs a PocketBeagle2's EEPROM automatically when needed, and rechecks a board's identity at every startup instead of trusting a stale cached value.
- **The File Manager's "Config" tab (developer mode) now has the same sort and filter controls as every other tab** — it had been missing them. (credit jessica12ryan) The eleven File Manager tables were also consolidated to build their options from one shared template, so a future fix only needs to be made once; this also quietly fixed lists that claimed to sort by name but never actually did.

## Upgrade note

Boards that were sharing a duplicate identity because of an old baked-in machine ID will get a new, unique UUID the next time they boot on this build. If you have a remote, script, or integration that keyed off a specific FPP board's UUID, expect it to change for any board that was affected.
