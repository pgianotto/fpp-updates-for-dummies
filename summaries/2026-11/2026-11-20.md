# FPP Updates — November 20, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

3 commits, all from Daniel Kulp, cleaning up media playback behind the scenes (memory use and log noise) and taking a first step toward PocketBeagle 2 support on the BeagleBone Black SD image.

## Video and audio

- Finished video tracks now hand their freed memory back to the system a few seconds after closing, instead of holding onto it for next time. On a Raspberry Pi 4 remote looping a 15-second video for several hours, this kept memory use roughly 40 MB lower than before.
- A looping video clip no longer floods fppd.log. Previously, every single pass of a loop wrote several lines to the log — about a thousand lines an hour during normal playback. Those routine lines now only show up at the more detailed debug log level; real warnings, and the signal that memory may be slowly leaking, still show up as before.

## Outputs and hardware

- The BeagleBone Black SD card image, when used on a PocketBeagle 2 board, previously did nothing at all — the board just looked dead. It now loads the PocketBeagle 2's own bootloader and blinks its four onboard LEDs to confirm the board is alive, with no change in behavior for actual BeagleBone Black boards using the same image.

## Upgrade note

If you have a script or log-monitoring tool that scans fppd.log for the per-loop playback lines (track start, "started playing", the free-memory line), note that those now log at the debug level rather than warn/info, so they won't appear at FPP's default log level.
