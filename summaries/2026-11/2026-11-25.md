# FPP Updates — November 25, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

7 commits from November 25: five from Daniel Kulp and two from darylc, covering audio/video sync timing accuracy, a couple of fppd web-server stability fixes, and MultiSync/diagnostics identity fixes.

## Playback and audio

- Fixed a small timing error in the on-screen song position — the number sequences follow and that MultiSync sends to other players. On systems using PipeWire for audio, the position could run up to about 17ms ahead of what's actually heard, and the gap was largest right after a show resumed from a pause. The position now tracks the sound card's own real queue instead of a declared, idealized delay, which keeps it within about 1ms. A debug log line that could misleadingly report a timing "correction" that hadn't actually happened was also cleaned up.
- Fixed a rare crash tied to a timing/locking bug that could happen when a display's audio output couldn't accept more data — for example, if it ran out of buffer space.

## Stability fixes

- Fixed a bug that could hang fppd (freeze the player, requiring a manual restart) if a restart command arrived in the brief window right as the web server was starting up — this could happen, for instance, when a scheduled playlist's first entry triggers an "FPPD Restart."
- Fixed a related crash in the web server's shutdown that could occur on some newer Linux systems (such as Debian 13) if stopping or restarting FPP took a little longer than usual.

## MultiSync and diagnostics

- Fixed MultiSync not recognizing that pings from the same sending player, seen across more than one network address (for example, wired and WiFi), belong to one device — its real identity now correctly carries over to all of its listed addresses. (darylc)
- Fixed the diagnostics "duplicate hostname" warning so it counts actual devices instead of network addresses. A single FPP player reachable on two interfaces, or over both IPv4 and IPv6, no longer falsely triggers a "multiple devices sharing a hostname" warning. (darylc)
