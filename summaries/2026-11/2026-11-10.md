# FPP Updates — November 10, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

2 commits, one from Daniel Kulp and one from community contributor darylc, both fixing reliability issues: a stuck "stop" during a restart, and a false warning in Docker setups.

## Stability fixes

- **Stopping FPP right after a restart now actually stops it.** If you restarted FPPD (or switched modes) and then quickly told systemd to stop it, the stop signal could get lost during the restart's handoff to the new process, leaving the old FPP running until systemd forcibly killed it a couple of seconds later. Stop requests are now honored during that handoff, so FPP shuts down cleanly instead.

## System and UI

- **Docker containers no longer show a permanent "mDNS/Avahi client failure" warning (#43).** Nothing in the container was starting the system message bus or network-discovery service that FPP's warning check relies on, so the warning never cleared. Docker startup now starts both automatically when they're available. (darylc)

## Upgrade note

If you run FPP in Docker, startup now also launches D-Bus and Avahi (when installed) before FPP itself starts. On the default bridge network the warning clears but the player still won't be discoverable from outside the container; host or macvlan networking is needed for discovery to actually work.
