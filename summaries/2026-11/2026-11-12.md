# FPP Updates — November 12, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

26 commits, 25 from community contributor darylc and one from Daniel Kulp. It was a cleanup day: small reliability and consistency fixes spread across OS upgrades and multisync, playlists and overlay models, output hardware, and the web interface, with no new features.

## MultiSync and updates

- **The OS upgrade dialog can now be closed as soon as it says "Rebooting"**, instead of being stuck open waiting for a response from a player that's already restarting (darylc).
- **OS upgrades finish more cleanly.** The upgrade page's response is sent before the player reboots, so the reboot no longer leaves the request hanging (darylc).
- **A failing download mirror during an OS upgrade now falls back to GitHub after two quick tries, not twenty**, so a slow or dead local mirror doesn't stall the upgrade (darylc).
- **An update blocked because another update is already running now correctly reports an error**, instead of looking like it succeeded (darylc).
- **MultiSync now shows a remote player as failed, not successful, when it refuses a reboot, shutdown or restart request** (darylc).
- **Turning off Broadcast or Multicast sync now actually stops sync going out that way after an upgrade**, instead of the old setting sticking around (darylc).
- **A remote player that fails to respond to a remote action is now reported as a server error rather than a bad-request error**, making real problems easier to spot (darylc).

## Playback and playlists

- **Overlay Model Text entries keep their "Auto Enable" setting and their text when upgraded**, instead of losing them (darylc).
- **Deeply nested, looping sub-playlists no longer eat up all of PHP's memory.** Sub-playlist lookups now stop after 5 levels deep (darylc).
- **The old Channel Memory Maps file is kept around until its models have actually been saved**, with its eventual removal now planned for later, so nothing is lost mid-transition (darylc).
- **Restoring a backup that includes the old Channel Memory Maps area no longer overwrites your Pixel Overlay Models** (darylc).

## Outputs and hardware

- **A cape's EEPROM is no longer accidentally wiped when FPP gets a "signed" reply but can't find a valid EEPROM for that cape** (darylc).
- **E1.31 Clone no longer lets you add one row too many before complaining, and now asks you to select a row first** (darylc).
- **The Opus RTP, VBAN and AES67 audio interface lists keep interfaces like `wlo1` and drop the confusing `@<link>` suffix some interfaces had** (darylc).
- **Muting an audio input, source or route in PipeWire now flips its button correctly**, so the next click unmutes it instead of muting it again (darylc).
- **WLED's `/json/palx` palette list is now keyed by palette ID, matching how WLED itself does it** (darylc).
- **Ports wired after a Differential expansion board are no longer incorrectly drawn as differential ports** (darylc).

## System and UI

- **The status page's received-packets table now always splits into three columns above 96 input universes**, instead of behaving inconsistently depending on the exact count (darylc).
- **Removing or moving a condition inside a third-level group no longer brings back the "+ Add Group" button by mistake** (and the Expression field's help text now clarifies that names are inserted bare) (darylc).
- **A dialog that's closed while still fading in now actually closes once it finishes showing**, rather than staying stuck open (darylc).
- **A StreamURL error message is now shown once, not twice** (darylc).
- **Models with an apostrophe in their name are no longer lost when saved** (darylc).
- **FPP's status now reports its current host description, not the one it started up with** (darylc).
- **Storage device settings now match the root device correctly instead of mismatching similarly-named devices** (darylc).
- **The file manager's script tab sets up its file table correctly when that's the tab the page opens on.**

## Upgrade note

- Sub-playlist nesting is now capped at 5 levels deep — a playlist relying on deeper nesting will stop there instead of looping indefinitely.
- Unticking Broadcast or Multicast in MultiSync now actually takes effect after an upgrade; if you relied on the old (ineffective) toggle, sync behavior may change.
