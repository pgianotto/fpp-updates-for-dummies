# FPP Updates — November 7, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

9 commits: 6 from darylc and 3 from Daniel Kulp. The main themes were MultiSync fixes, crash handling, and cape/sensor hardware. All landed on November 7 (five of them in the early morning hours).

## MultiSync and playlists

- **Syncing to a different media entry now works properly.** A plugin that told a MultiSync player to jump to another media item left the old media playing and never started the new one, while telling remotes to stop a file they weren't playing. It now stops what is actually playing and starts the new item (darylc).
- **MultiSync discovery ranges typed as a host address now scan the whole network.** If you entered a range starting from a specific host address instead of the network address, it previously didn't scan correctly (darylc).

## Video and audio

- **Video on an overlay model lights up again after an output reload.** Reloading outputs could leave a video model dark (darylc).
- **AES67 audio: conflicting resample settings are handled.** If "driftResample" is on, "adaptiveResample" is now ignored with a warning in the log instead of the two fighting each other (darylc).

## Outputs and hardware

- **Analog sensors on some I2C/SPI chips (e.g. AD7998) now read real values.** Previously every channel read 0 on these chips. FPP now reads them in a way that works, and falls back to a simpler method if the first is refused.
- **Pi capes with microcontroller-based EEPROMs are more reliable to write.** The kernel's wait time for EEPROM writes is raised so the cape's flash erase doesn't cause failures. New Pi images get it automatically and an upgrade step adds it to existing installs; it takes effect after the next reboot.

## Stability fixes

- **A second memory-access crash on another thread no longer kills FPP outright.** FPP survives it the same way it survived the first (darylc).
- **Crash report requests are answered more safely** by the web server, avoiding a rare timing problem when the report is generated.
- **Uploads via HTTP PUT now send a proper content length** rather than chunked, which some servers reject (darylc).

## Upgrade note

- Raspberry Pi installs get a one-time change to the boot command line (`at24.write_timeout=1000`) during upgrade; reboot to apply it.
