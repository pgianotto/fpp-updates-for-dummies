# FPP Updates — October 14, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

All from Daniel Kulp: plugin upgrades without a restart, video slots that stay ready between videos, and a round of crash and correctness fixes.

## New features

- **Plugin upgrades:** upgrading a plugin reloads it in fppd instead of needing a restart.
- **Video slots:** a slot's overlay and RTP outputs stay built between videos, so the next video starts faster.

## Video and audio

- Overlay and RTP outputs get the start of a video, and playback ends on time.
- A video with no audio track plays at its own speed even with no display attached.
- dB-scaled mixer controls are set to 0 dB rather than 100%.
- MP3Gain in File Manager now applies the gain instead of only analyzing it.

## Stability fixes

- A plugin that never answers, or a wrong-typed AES67 setting, can no longer stop fppd starting.
- The WLED API handles what WLED apps send and stops leaking threads.
- A malformed device reply no longer stalls MultiSync discovery.
- 16-bit framebuffer models are no longer drawn black.
- The newest request for a model wins over its running effect; Stop Effects on a disabled model stops at once.

## Playlists and scheduler

- Starting a playlist part-way in keeps the whole playlist loaded.
- Image entries draw without a cache folder; folder entries only pick up images.
- Holiday and Locale changes take effect without restarting fppd.
- Ramadan 2031–2035 and Eid al-Fitr 2034–2035 fall on the right dates.

## Outputs and tools

- KiNet v2 sequence numbers no longer skip at playback start.
- Pixel counting via current sensors counts weak pixels on noisy sensors.
- Output Specific tests count their cycles again.
- `fpp --log-level` works again, and `fppmm -f` copies a file into a model through the API.

## Security

- An unsigned cape can no longer copy a file using a relative path.
