# FPP Updates — October 18, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

63 commits from Daniel Kulp: a large security and robustness pass, with output configs checked against the channel data and many reload races fixed.

## Security

- Files served through the file API can't run as web pages, and no PHP runs from the virtual display assets folder.
- An unsigned cape can no longer run shell commands or rewrite the boot config.
- Tethering network names and passwords, and interface names, can't be run by the shell.
- The URL command and video downloads only fetch http(s) addresses, with a size cap; remote actions only reach other players.
- Path checks no longer let a similarly named sibling folder through.
- **State-changing GET API routes are now marked deprecated.**

## Audio and video

- A stall in the audio graph no longer leaves every later song behind its lights.
- Wrong-typed video and RTSP config entries are skipped, not fatal.

## Outputs

- Configs that would write past the channel data are refused (X11 Matrix, DPI Pixels, MAX7219, ILI9488, LED panels, network universes, processors, pixel-string ports, virtual display).
- A BBShiftPanel PRU that stops answering no longer hangs startup; PCA9685 keeps its servo position across a reload.
- Status pages, test patterns, GPIO, sensors and submodels no longer race an output reload.

## Stability

- A flood of input packets no longer holds up the main loop.
- Limits added to the MQTT cache, MultiSync discovery, Twinkly probes and image decoding.
- Listing FPP variables no longer deadlocks; scheduler command entries with complex arguments no longer abort fppd.

## System and boot

- The RTC tool no longer waits forever with no clock chip; cape detection no longer crashes or hangs on bad files.
- Exported source trees no longer show version "Unknown".
- The browser-based UI tests moved to the fpp-tests repository.

## Upgrade note

Scripts or integrations that change FPP's state with GET requests should switch to POST; those routes are planned for removal in FPP 11.
