# FPP Updates — October 16, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

56 commits from Daniel Kulp working through a code review item by item, hardening plugins, MultiSync, WLED, GPIO and networking against bad input, hangs and crashes.

## Plugins

- A plugin that throws an error is contained instead of taking fppd down, and its API calls return an error.
- fppd waits only a limited time for a script plugin, and no longer exits if starting one fails.
- Plugin internal API routes are blocked however the URL is capitalized.

## GPIO and hardware

- The Pi 5 GPIO chip is found by name, and PWM no longer leaks open files.
- FPP refuses to drive a pin set up as an input.
- Fixes for libgpiod v2, oversized I2C writes and the PRU state file.

## MultiSync and network

- The MultiSync sender and receiver were hardened, with limits on stats, remote lists and discovery.
- Discovery pings are answered without stalling, and FPP no longer runs its own broadcast commands twice.
- MQTT disconnects cleanly; the DNS cache is flushed only when the network actually changes.
- Ping, download-size and controller-detection limits prevent hangs on bad replies.

## WLED

- The WLED responder handles malformed requests and caps what it buffers; invalid audio-sync values are rejected.

## Scheduler, playback and variables

- Sun-relative offsets are range-checked and schedule expansion is bounded.
- A hard stop only affects what is playing now; a failed script entry can't signal the wrong process.
- Variable expressions and saved settings got correctness fixes.

## Outputs

- eFuse retries stop on a port that's turned off, and its warnings clear when a port is reset.
- The input bridge was hardened against malformed data.

## fppd and command line

- Crash, shutdown, command socket, timer and recurring task fixes.
- A one-byte overflow in the `fpp` command-line reply was fixed.
- Volume changes run in the background instead of blocking.
