# FPP Updates — October 31, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

6 commits, five from Daniel Kulp and one from Claude, covering a new way for plugins to push live updates plus a handful of startup and reliability fixes. Three of the commits landed in the early hours of October 31 and the rest by mid-morning.

## New features

- **Plugins can now push live updates to web pages.** C++ plugins can open their own WebSocket connection, the same way they already add their own API endpoints, so a plugin's page can show live data without constantly asking for it. Needs FPP 10.4 or newer, and the developer docs now explain how to set it up.

## MultiSync and updates

- Copying files to or from a remote FPP no longer waits around when that remote is switched off or unreachable. FPP now gives up on the remote after 15 seconds instead of stalling for about two minutes on every folder.

## Stability fixes

- **Settings changes are no longer ignored after a settings file is swapped out.** If something replaced the settings file (a script, an editor, or a restore), the running FPP could stop noticing later changes until it was restarted. It now keeps watching.
- FPP now starts on systems that have no IPv6 support instead of failing at startup.
- FPP's startup no longer crashes when the disk tool it uses to check for unused space is missing or prints nothing (Claude).

## Upgrade note

- Plugin authors: the new WebSocket calls are optional and only exist in FPP 10.4 and later. Plugins that use them should check that they are available so they still load on older versions.
