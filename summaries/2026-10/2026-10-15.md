# FPP Updates — October 15, 2026

*Unofficial, AI-written summary of the day's commits to FPP master. See the [commit log](https://github.com/FalconChristmas/fpp/commits/master) for the details.*

17 commits from Daniel Kulp: PRU-driven serial output on BeagleBone cape pins, image display fixes on framebuffer outputs, and tidier mDNS naming.

## New features

- **Serial from any cape pin:** a serial output can now be sent from a PRU on a cape pin that has no hardware UART transmit.
- Pins that can't transmit, and the console pin, are refused for serial outputs. The PocketBeagle 2 pin tables use the board's own port names.

## Image display

- The next image no longer overwrites one still being drawn.
- Transitions stay on screen and finish on the whole image; an image arriving mid-transition is drawn.
- A framebuffer device that can't be opened is reported.

## Network

- The player's mDNS host name is restored if the system renames it at boot, and a temporary "<host> #2" name no longer sticks.
- Location lookup falls back to a second service when the first is rate limiting.
- Twinkly only uses a login token after the device accepts it.

## Stability

- Several values shared between threads are now handled safely, and per-frame work got a little lighter.
